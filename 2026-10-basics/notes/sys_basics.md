# 计算机系统基础支线（W7—W14）

> 建立：2026-10-24
> 性质：**并行支线**，不动主线。每周 1.5 小时，共 8 周约 12 小时。
> 定位：不是学通 408，是**能答出面试官问的那 30—40%**。

---

## 一、为什么开这条线

面经硬数据：应用向算法岗（Agent / RAG）的面试里，**30—40% 是开发基础题**。

| 公司 / 岗位 | 开发基础题占比 | 具体题目 |
|---|---|---|
| 百度 · AI 智能体算法（一面） | **11 题全部** | JVM 生命周期、Full GC 定位、任务调度器、happens-before、MySQL B+Tree、联合索引最左前缀、间隙锁、Redis 持久化、分布式锁 |
| 蚂蚁 · AI Agent 应用（12 题） | 3 题 | MySQL 索引为什么选 B+ 树、Python GIL 与多线程、数组实现栈（O(1) 最小值 + 线程安全） |
| 滴滴 · AI Infra（开发基础 3 题） | 3 题 | 线程池参数、进程/线程/协程区别、HashMap 原理 |

**这块在你日历里目前是空白。** 不补，投算法岗会被问倒；真要转 AI 工程岗更绕不过去。所以它是**双投的公共投资**，不是为转岗准备的。

---

## 二、目标（明确且有限）

**要达到：** 面试官问"为什么这么设计"，你能用 3 句话讲清。
**不要求：** 能手写 B+ 树、能手写线程池、能背 JVM 参数。

判据：给你一道面经真题，30 秒内能说出"是什么 → 关键点 → 为什么/坑"。

---

## 三、内容按「面试出现频率」排，不按教材顺序

| 优先级 | 主题 | 面经出处 | 必须能答的问题 |
|---|---|---|---|
| **P0** | 数据库 · 索引原理 | 百度、蚂蚁（2 次） | 为什么用 B+ 树不用 B 树 / 不用哈希？为什么适合范围查询？ |
| **P0** | 数据库 · 联合索引 | 百度 | `(tenant_id, status, created_at)` 什么时候用不上索引？最左前缀是什么？ |
| **P0** | 并发 · 进程/线程/协程 | 滴滴 | 三者区别？什么时候用哪个？ |
| **P0** | 并发 · Python GIL | 蚂蚁 | 全局解释器锁是什么？为什么多线程跑不满多核？CPU 密集该用什么？ |
| **P1** | 数据库 · 事务与锁 | 百度（间隙锁） | 四个隔离级别各解决什么问题？间隙锁为什么会死锁？ |
| **P1** | 并发 · 线程池与锁 | 百度、滴滴 | 线程池几个核心参数？锁竞争怎么减少？happens-before 解决什么？ |
| **P2** | Redis | 百度（3 题） | RDB 和 AOF 怎么选？分布式锁怎么避免误删？ |
| **P2** | 网络最小集 | 面经没出现，但开发岗通识 | TCP 三次握手为什么不是两次？HTTP 和 HTTPS 差什么？ |
| **跳过** | JVM | 百度（但只投 Java 岗才需要） | 不学 |
| **暂缓** | OS（进程调度 / 内存管理） | 面经没出现 | 有余力再说 |

> **注意一个能省时间的事实**：你 W5 已经刷完 SQLBolt 全部 14 课，**SQL 语法你已经会了**。
> 缺的不是"怎么写 SQL"，是"**索引为什么这么设计**"。这两件事完全不重叠，只补后者即可。

## 五、每周 1.5 小时怎么花

| 时长 | 动作 |
|---|---|
| 40 min | 只看一个主题，**且只挑面试问的角度**（不顺着教材往下读） |
| 20 min | 写进本文件对应小节，3—5 条，每条一句话，必须带数字 |
| 30 min | 挑一道面经真题**口述并录音**，回放听自己哪里卡住 |

## 六、时间从哪来（不额外加负担）

你现在超前日历约 11 天（1.7 周）。按每周 22 小时折算，这段缓冲约 **30 小时**。

支线总需求 = 8 周 × 1.5h = **12 小时**。

**用缓冲支付，绰绰有余，主线 20—25 小时不动。**

## 七、边界（明确不做什么）

- ❌ 不系统学 408 四门课
- ❌ 不学 JVM（除非将来真投 Java 岗）
- ❌ 不手写数据结构实现（除面试明确要求的，如最小栈）
- ❌ 不追 OS 深水区（进程调度算法、虚拟内存页表）
- ❌ 不影响主线节奏：**主线任务没完成时，支线当周跳过，不补**
