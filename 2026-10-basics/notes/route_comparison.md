## 二、三条真实正反馈（可直接采纳）

### 1. minimind.wiki 的「CPU 小数据实验」补上我们的快速迭代能力

我们的 W7 第 4—5 段在 6GB 上训练字符级 LM，**改一个超参跑一次要等**，这直接压制了「对照实验」的频率。
minimind.wiki 的做法是：**学习阶段用 TinyShakespeare（1MB）在 CPU 上跑，几分钟出结果。**

**动作**：W7 第 5 段之后，**超参对照一律在 CPU + 小数据上做**，GPU 只留最终验证。成本约 1 小时，收益是把「做一次实验」从 30 分钟压到 3 分钟。

### 2. MiniMind 是 W9—W13 的现成参照实现（解决一个真实悬空问题）

日历 W9（SFT）、W10（LoRA/QLoRA）、W13（DPO）**代码来源至今没定**。MiniMind 给的是：
`pretrain.py` / `train.py`（SFT）/ `train_lora.py` / `train_dpo.py`，且兼容 trl + peft —— 与 W8 要学的 `Trainer` 同一套生态。

**最高价值点**：它的 DPO 实现可以对照读，比啃论文快，正好补我们识别的 **RL 对齐缺口**。

**红线**：直接跑通 MiniMind ≠ 你的项目。面试问「你做了什么」，答「我跑了 MiniMind」是减分项。
**必须在它上面做变量改动**：换数据域、换 rank、换 `target_modules`、做单变量对照 —— 那才是项目一。

### 3. hello-agents 补 W15—W18 的中文 Agent 教材

我们日历 W15—W18 只有「HF Course」+ 项目二（RAG + LangGraph），**中文 Agent 体系教材是空白**。
hello-agents 的「进阶提升」模块（记忆检索、上下文工程、MCP/A2A、Agentic-RL、性能评估）精确对上我们 W15—W18 的八股主题（RAG 检索指标、Agent 可靠性）。

**动作**：只取「核心实战 + 进阶提升」两块，**跳过三个大项目**（智能旅行助手 / 深度研究 / 赛博小镇）—— 你已有项目二，重复做只会挤掉 vLLM 和投递准备。

## 四、两条必须警惕的

### 1. CS336 对你性价比最低

- **A1（tokenizer）+ A2（Transformer）你已经做过等价物**：W7 手写 BPE、W6 手写 attention / MHA / RoPE / causal mask，并且对齐到 1e-8
- 真正的增量在 A4（scaling law）/ A5（数据），**但需要大算力，且不属于应用向算法岗的面试核心**
- 作业 A3（训练）与你 W7 第 5 段部分重叠

**建议：只看 lecture，不做 assignment；或直接跳过。你需要的是 offer，不是课程完成度。**

### 2. Agent 部分的体量与你的时间线冲突

hello-agents 五模块 + learn-claude-code + nanobot ≈ 2—3 个月。你日历 W15—W18 只有 **4 周**。
按它的深度走会挤掉 W19—W22（vLLM/推理服务）和 W23（投递准备）。

**建议：W15—W18 只取 hello-agents 的「核心实战 + 进阶提升」，其余旁听。**

## 六、技术风险提醒

MiniMind 在 Windows 上有已知坑：
- `pip install` 时 numpy metadata 生成失败
- 部分用户 DPO 训练输出乱码（代码未改）
- VLM 预训练 loss 异常偏高（约 7.5）且无明确解法

**你在 Windows + 6GB，不要在装环境上耗时间。** 两条路：
1. 用 minimind.wiki 的 CPU 实验（零 GPU 风险）
2. 走 WSL2（正在装）后再碰 MiniMind 主项目

## 七、第二次外部路线：“双线并行、工程先行”（2026.10.31）

### 对方主张（原文要点）

纯算法岗需要顶会论文 + 深度项目 + 高竞争门槛，所以研一不 all in 算法，采取“双线并行、工程先行”：先从 Agent 开发等应用落地切入，做 1–2 个有深度项目（微调 / RAG / Agent 工程），研一下学期据此锁定研究方向，研二用实习积累竞争力。算法是长期目标，项目与实习是当下抓手。

### 逐条对齐本日历

| 对方主张 | 本日历对应 | 判断 |
| --- | --- | --- |
| 研一下学期锁定研究方向 | W23（2027.03.01—03.07）“只选一个主投方向” | 时间点完全重合（研一下学期=2027.02—07） |
| 研二用实习积累竞争力 | W24 启动日常实习投递；2028.03—05 暑期主战场 | 本日历早一年启动 |
| 做微调 / RAG / Agent 落地项目 | 项目一 LoRA 微调评测、项目二 RAG+Agent、项目三 vLLM | 覆盖更全：多一个推理服务项目 |
| 不 all in 纯算法 | 已定“算法岗 + AI 工程岗双投” | 同一策略 |
| 工程先行（先 Agent，后原理） | 本日历自底向上：原理 → 微调 → RAG/Agent → 推理服务 | **唯一实质分歧** |

### 唯一实质分歧：顺序

对方是“先会用，再懂为什么”；本日历是“先懂机制，再用”。

对本日历更优的三条理由：

1. **能力已形成**：W1—W7 已完成手写 MHA（对齐官方 2.98e-08）、BPE、字符级语言模型全流程训练与恢复。改走工程先行等于弃掉已建成的地基。
2. **面试证据**：面经显示应用向算法岗 30—40% 是开发基础题，且追问方式为“不问了解吗，直接问为什么”。工程先行者的典型短板正是“结论对、机制空”。
3. **工程深度依赖原理**：RAG 召回上不去要调切分与 embedding，Agent 工具调用失败要看 token 级行为与上下文窗口。没有 tokenizer / attention 基础，调优只能靠试。

### 采纳：一条

**“1–2 个有深度项目”而非三个平铺。** 本日历三个项目等权重推进，风险是三个都浅。动作：项目一（领域问答 LoRA 微调 + 评测 + 消融）定为主项目，简历首屏；项目二、三定位为支撑（证明应用面与工程面），不追求同等深度。

### 不采纳：两条

| 主张 | 理由 |
| --- | --- |
| “纯算法岗需要顶会，所以不 all in 算法” | 前提只对训练向成立。应用向算法岗的实证门槛是“一篇 2 区一作”（面经中已进京东 / 蔚来 / 百度者）。本日历本就不走训练向，无需为顶会让路。 |
| “工程先行能更快出成果” | 该路线无验收标准，“有深度”无法判定；本日历有表 2 验收 + 逐周对账 + 可量化数字。快不快取决于能否判定完成，而非先后顺序。 |
